# OneSMTP 0.2.0 Admin Accessibility QA

Use this checklist for release-readiness review of the 0.2.0 admin surfaces. Keep test data neutral and synthetic.

## Scope

- Dashboard metrics, pending messages, provider activity, and empty states.
- Setup wizard provider forms, provider capability matrix, test email form, completion states, and setup notices.
- Provider management forms, provider table, active/inactive/delete controls, safe config, and credential recovery messaging.
- Email log list, filters, pagination, CSV export, detail view, attempt lineage, manual resend, and empty/filter-empty states.
- Queue diagnostics summary, scheduler availability, overdue retries, recommended recovery actions, and scheduler/provider admin notices.
- Sender identity, delivery rate limit, and failure alert settings.
- Mail conflict warning and dismiss control.

## Automated Coverage

- `tests/Unit/Admin/AdminAccessibilityMarkupTest.php` verifies labeled navigation, form labels, scoped table headers, contextual action labels, keyboard-reachable links/buttons, long-content wrapping, privacy-safe copy, empty states, notices, export links, pagination, and resend controls.
- Existing admin unit tests continue to verify capability denials, nonce-protected mutations, redacted log output, safe CSV export, provider credential recovery messaging, dashboard empty/activity states, queue diagnostics, and notice visibility.

## Manual Keyboard And Focus Pass

- Open `wp-admin/options-general.php?page=onesmtp` as an administrator with synthetic providers and logs.
- Use only the keyboard to move through Dashboard, Setup, Providers, Logs, Diagnostics, and Settings section tabs.
- Confirm every link, select, text field, checkbox, submit button, CSV export link, pagination link, resend control, and notice dismiss button receives visible focus.
- Confirm focus order follows the visual reading order and does not skip repeated provider row actions, log filters, or manual resend controls.
- Confirm Escape, Enter, Space, Tab, and Shift+Tab behave according to native browser and WordPress admin expectations. There are no custom modals in 0.2.0 scope.

## Semantics And Labels

- Confirm each form control has a visible label or contextual `aria-label`.
- Confirm data tables expose column headers and row headers for screen reader navigation.
- Confirm notices use specific action text, such as `Configure providers`, `Review diagnostics`, `Review queue diagnostics`, and `Remind me later`.
- Confirm empty, success, failure, unavailable scheduler, no provider, no eligible resend provider, and credential recovery states announce the state in visible text.

## Privacy And Long-Content Checks

- Use synthetic domains such as `example.test` and synthetic provider names.
- Do not use real credentials, recipients, message bodies, headers, payload JSON, provider secrets, or production logs.
- Confirm dashboard, logs, CSV export, queue diagnostics, and failure alert copy summarize operational state without exposing raw recipients, message bodies, headers, payloads, credentials, or provider secrets.
- Confirm long provider names, long safe config values, long webhook URLs, long provider message IDs, and long error contexts wrap instead of forcing horizontal overflow.

## Visual Review

- Confirm WordPress admin focus outlines remain visible.
- Confirm notice colors, button states, table striping, and form layouts remain readable in the default WordPress admin color scheme.
- Confirm no text overlaps in narrow admin viewports.
- Confirm contrast issues are not introduced by plugin-specific styles. The 0.2.0 admin surfaces rely on WordPress admin styles and inline wrapping only.
