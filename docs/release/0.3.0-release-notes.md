# Aculect Mail 0.3.0 Release Notes

Status: release candidate documentation. Publishing a release remains an owner-approved action.

## Highlights

- Adds Zoho Mail, Emailit, and Netcore to the provider catalog.
- Adds email queue management, delivery attempt logs, eligible-provider failover, switchover metrics, and provider reliability reporting.
- Adds a quiet SureMail compatibility card and an opt-in importer that analyzes the installed configuration before importing one default connection per provider. Imported credentials are decrypted in memory and re-encrypted with Aculect Mail's AES-GCM vault; logs are not imported and SureMail is never deactivated automatically.
- Adds an explicit simulation mode for staging. Aculect-owned mail is recorded as `Simulated` without contacting a provider or being reported as delivered.
- Reworks Providers into one row per provider with `Connect` changing to `Manage`, an inline setup flow, and a test-email step.
- Uses WordPress components and DataViews through lazy-loaded admin modules so advanced interfaces do not block the initial screen.

## Reliability And Safety Changes

- Aculect Mail detects when SureMail replaces the WordPress `wp_mail()` function. In that state it does not claim delivery readiness, cannot enable simulation mode, and pauses its scheduled sends without losing their queued state.
- Failover distinguishes provider-scoped failures from message-scoped terminal failures. Invalid-recipient and policy outcomes no longer mark a provider unhealthy.
- Emails with attachments remain synchronous and route only through adapters that explicitly support attachments. Generic SMTP validates and attaches readable files; unsupported background retry paths fail safely instead of silently dropping files.
- Provider test emails use sender identity, receive a stable Aculect message UUID, and create the same privacy-safe log and attempt lineage used by production delivery.
- Emailit receives a stable idempotency key, and Zoho Mail refreshes OAuth access tokens from stored refresh credentials using the selected Accounts region.
- The one-provider/one-connection rule is enforced for create and update paths with a short atomic option lock to reduce duplicate writes.

## Upgrade Guidance

1. Back up the WordPress database and test the upgrade on staging.
2. Open Aculect Mail > Providers and confirm which plugin owns live delivery.
3. If SureMail is installed, analyze compatibility and import only when the preview is valid. Test the inactive imported connection before switching delivery ownership.
4. Re-save Zoho Mail connections with account ID, client ID, client secret, refresh token, and the correct Accounts region.
5. Confirm Action Scheduler health, sender identity, provider priority, and queue state.
6. Send test messages through the primary and backup providers, then confirm the email log, attempt lineage, and switchover metric.
7. Use simulation mode only after Aculect Mail owns delivery; it cannot intercept mail sent by another plugin's replacement `wp_mail()` implementation.

## Known Boundaries

- No plugin can guarantee 100% inbox delivery. Provider acceptance, DNS authentication, recipient policy, and downstream mailbox processing remain external.
- API adapters that do not explicitly implement attachments are excluded from attachment delivery rather than accepting a send that could lose files.
- The legacy `onesmtp` directory, text domain, PHP namespace, REST route, database tables, and stored option keys remain unchanged for upgrade compatibility.
- Real-provider verification requires owner-supplied staging credentials and a disposable test inbox; automated tests use fakes and do not transfer credentials.

## Required Release Proof

- PHP unit and integration suites, changed-file coding standards, PHPStan, JavaScript lint, production build, E2E admin smoke, package inspection, and `git diff --check` all pass.
- Fresh visual checks cover Overview, Providers, Activity, Analytics, Settings, and Advanced at desktop and narrow viewport widths.
- At least one staging test confirms live provider delivery and one controlled failure confirms eligible-provider switchover.
- Release packaging and publication are performed only after explicit owner approval.
