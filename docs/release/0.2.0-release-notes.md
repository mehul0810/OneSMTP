# Aculect Mail 0.2.0 Release Notes Draft

## Highlights

- Operational reliability release focused on admin observability, safer diagnostics, queue visibility, and provider health context.
- Admin workflows now cover provider circuit health, source attribution, dashboard metrics, log filtering/export, bulk resend, and weekly delivery summaries.
- Privacy-safe diagnostics and settings import/export keep provider secrets, recipient destinations, headers, message bodies, payloads, and raw attachment content out of release-facing reports by default.

## Reliability Changes

- Retry scheduling fails closed when Action Scheduler is unavailable and records a scheduling failure event.
- Terminal, authentication, and policy failures stop retry scheduling early while preserving redacted log context.
- Optional rate limits defer mail through Action Scheduler when per-minute, hourly, or daily capacity is exhausted.
- Optional background sending queues normal mail while keeping provider tests and manual resends synchronous.

## Operational Changes

- Email logs now support safer filtering, CSV export, detail actions, manual resend, bulk resend, source attribution, and optional attachment metadata logging.
- Diagnostics now include privacy-safe admin and WP-CLI summaries for provider state, scheduler health, queue state, and recent failure categories.
- Provider setup includes DNS readiness guidance and capability-matrix documentation for supported delivery, testing, OAuth, attachment, and message identifier behavior.
- Admin release-readiness coverage includes accessibility QA notes for keyboard navigation, notices, tables, forms, and long-content states.

## Upgrade Notes

- No production tag, release asset, or package publication is created by this release-candidate prep.
- Review the package checksum, browser smoke, and Node build evidence before approving a production 0.2.0 release.
- Confirm Action Scheduler is available on target sites before enabling background sending, rate-limit deferral, or retry workflows.
- Reconfirm provider credentials, sender identity settings, DNS readiness, and alert destinations in a staging site before rollout.
